Introdução ao Controle de Versão e ao Git

Bem-vindo ao mundo do versionamento de código! Imagine o Git como uma "máquina do tempo" superpoderosa para os seus projetos. Em vez de criar pastas confusas como projeto_final, projeto_final_agora_vai e projeto_final_v3, o Git registra cada alteração que você faz no código de forma estruturada. Ele permite que você trabalhe em equipe sem sobrescrever o trabalho do colega, reverta erros com facilidade e mantenha um histórico limpo e profissional da evolução da sua aplicação.

Instalando o Git

Para começar nossa jornada, precisamos ter a ferramenta instalada na sua máquina. O processo é bem simples: baixe o instalador oficial de acordo com o seu sistema operacional. Durante a instalação no Windows, você pode deixar as dezenas de opções padrão marcadas (o famoso "Next, Next, Finish"). Elas são perfeitamente adequadas para quem está começando.

Acessar página oficial de download do Git

Configurando Nome e E-mail: A Sua Assinatura

Antes de começarmos a salvar as versões do nosso código, o Git precisa saber quem está fazendo as alterações. Cada "salvamento" (que chamaremos de commit) leva uma assinatura digital.

Qual nome e e-mail devo usar? Utilize seu nome profissional e, o mais importante, o mesmo e-mail que você usa (ou vai usar) para criar sua conta no GitHub. Isso é fundamental para que, no futuro, quando enviarmos nosso código para a nuvem, o GitHub consiga vincular o seu trabalho ao seu perfil público perfeitamente.

Abra o seu terminal e digite os comandos abaixo, substituindo pelos seus dados reais:

  1. git config --global user.name "Seu Nome Completo"
  2. git config --global user.email "seu.email@exemplo.com.br"

Colocando a Mão na Massa: Criando um Projeto

Vamos para um cenário do mundo real: você foi contratado para criar uma nova página web e precisa garantir que todo o desenvolvimento front-end seja versionado com as melhores práticas da indústria desde a primeira linha de código.

Iniciando a Pasta do Projeto

O primeiro passo é criar uma pasta comum no seu computador para abrigar o projeto. Dentro dela, crie um arquivo chamado index.html (pode deixá-lo vazio por enquanto). Agora, abra o terminal apontando para dentro dessa pasta.

Para transformar essa pasta comum em um repositório Git (ou seja, ligar o "radar" do Git nela), utilizamos nosso primeiro comando oficial. Ele criará uma estrutura oculta (a pasta .git) que passará a monitorar todas as suas edições:

Comando: git init

O Radar do Git: git status

Com o nosso repositório criado, você precisa conhecer uma ferramenta que será sua melhor amiga: o comando status. Pense nele como o "radar" ou a "lupa" do Git. Sempre que você estiver em dúvida sobre o que foi alterado, o que já está salvo ou o que falta salvar, basta perguntar ao radar.

Comando: git status

Se você rodar esse comando agora, o Git vai avisar (geralmente em texto vermelho) que encontrou o arquivo index.html, mas que ainda não está rastreando as mudanças dele. Para mudar isso, precisamos entender um conceito fundamental.

A Zona de Preparação (O famoso "Stage")

Diferente de salvar um arquivo no Word, o Git não salva tudo de uma vez automaticamente. Ele usa uma área intermediária chamada Staging Area (ou simplesmente Stage). Pense no Stage como uma caixa de papelão aberta em cima da sua mesa.

Você pode ir colocando os arquivos que alterou dentro dessa caixa aos poucos, organizando o que faz sentido ser salvo junto. O Git só vai registrar definitivamente na "máquina do tempo" os arquivos que estiverem dentro dessa caixa no momento em que você decidir fechá-la.

Colocando arquivos na caixa: git add

Para avisar o Git que você quer colocar o nosso novo arquivo na zona de preparação, usamos o comando add. É literalmente dizer: "Git, pegue este arquivo e adicione na caixa para o próximo salvamento".

  • Para adicionar um arquivo específico: git add index.html
  • Para adicionar tudo que foi criado ou modificado de uma vez (o famoso "ponto"): git add .

Dica de ouro: Se você rodar o git status novamente após o add, verá que o texto que era vermelho ficou verde! Isso significa que o arquivo já está na caixa, pronto para ser empacotado.

Fechando e rotulando a caixa: git commit

Com os arquivos no Stage, chegou a hora de selar essa versão oficialmente. Chamamos esse salvamento de commit.

A regra número um de um bom desenvolvedor é nunca fechar uma caixa sem colar uma etiqueta nela. Essa etiqueta é a mensagem do commit, que explica para o seu "eu do futuro" (e para a sua equipe) exatamente o que foi alterado ali, sem que precisem abrir o código para descobrir.

Comando: git commit -m "Cria a estrutura inicial do index.html"

O -m significa "message" (mensagem). Pronto! Em vez de criar uma cópia física da sua pasta chamada projeto_v1, agora você tem um ponto na história do Git registrado de forma limpa, profissional e auditável.
